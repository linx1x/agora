# Weather reference investigation

Investigated 2026-10-12 for Agora's first weather system: shared seasonal daily forecasts, clear/cloudy/rain/thunderstorm/snow, smooth visual transitions, and gentle crop/fishing/animal effects. These are Agora requirements, not claims that either reference game implements that exact combination.

## Findings and design implications

| Question | Observed reference behavior | Agora implication (design choice) |
| --- | --- | --- |
| Who decides weather? | Stardew `Game1.UpdateWeatherForNewDay` (`06000B68`, IL 37–69 and 104–175) gates daily updates on the master game and updates network location weather. `LocationWeather.UpdateDailyWeather` (`060020F9`, IL 0–136, 141–294) applies the previous forecast, computes tomorrow's date, handles festival exceptions, then chooses the first matching weather rule. XML `LocationContextData` confirms optional inherited context weather. | Compute the same forecast from world identity and day everywhere; share one authoritative clock/day. Resolve offline days using each historical day's forecast, not today's weather. |
| Smooth transitions? | Minecraft `ServerLevel.advanceWeatherCycle` (`aqu.au`) maintains rain/thunder timers and separate intensities. Bytecode 289–406 moves each intensity toward its target by 0.01 and clamps it to 0–1; 409 onward sends level-change packets. `Level` (`dcw`) stores old/current values for interpolation. | Keep daily gameplay state discrete while smoothly blending lighting, precipitation density and wind. Frame rate must not affect gameplay or forecast selection. Minecraft's exact timing is not copied. |
| Rain/snow assets and animation? | Stardew `Game1.drawWeather` (`06000C25`, IL 56–81) checks outdoors and snow. Snow uses a drifting, tiled overlay; rain uses `rainTexture`, each drop's position/frame, and sprite-sheet rectangles (IL 807–902). Rain positions are adjusted for player movement in separate methods. Minecraft `LevelRenderer.renderSnowAndRain` (`gex.a(gey,float,double,double,double)`) uses rain strength, a bounded camera neighborhood, biome precipitation and surface heights, then separate rain/snow textures. The JAR contains `textures/environment/rain.png` and `snow.png`. | Use original procedural precipitation or Agora assets, separate from character/world sprite sheets. Bound particle counts to the viewport; retain depth/readability and stable camera movement. Seasonal ground palettes remain distinct from falling snow. |
| Shelter and local conditions? | Stardew's precipitation draw stops indoors (IL 56–66), although context rain queries can still be true indoors (SD-DOC, `GameLocation.IsRainingHere`). Minecraft `Level.isRainingAt` (`dcw.r(jd)`, bytecode 0–69) checks global rain, sky visibility, surface height and the biome precipitation type. | Separate world weather from local exposure. Indoor scenes suppress precipitation; future roofs/greenhouses can use exposure without changing everyone's forecast. Do not infer that every covered tile is already simulated in Agora. |
| Crops and visible soil? | Minecraft `FarmBlock.randomTick` (`div.b`, bytecode 15–63) treats nearby water or rain above the block as hydration and sets moisture to 7. The archive contains both farmland and moist-farmland textures. Stardew `HoeDirt.dayUpdate` (`060019D6`, IL 53–78 and 147–174) passes existing soil state to crop growth before clearing nonretained water; this establishes ordering, not the complete rain-watering path. | Rain/thunderstorms water eligible outdoor soil. Preserve watering/growth order in day simulation, including catch-up. Wet-soil appearance should reflect actual soil state. Snow should not silently count as rain watering. |
| Fishing? | Stardew `GameLocation.CheckGenericFishRequirements` (`06000FB8`, IL 438–487) rejects fish according to rainy/dry requirements. Minecraft `FishingHook.catchingFish` (`cnl.a(jd)`, bytecode 16–78) conditionally increases timer advancement when exposed to rain and decreases it under blocked sky; subsequent timer code consumes that advancement. | A modest rainy-weather bite-speed or catch-table modifier makes weather useful. All reward-affecting rules belong in shared/server simulation. Agora's bonuses and fish eligibility are original balance decisions. |
| Animals? | Stardew `FarmAnimal.updateWhenNotCurrentLocation` (`060007CF`, IL 134–182) blocks the exit-home branch when it rains or is winter. `updatePerTenMinutes` (`060007D2`, IL 30–69) uses rain/winter in outdoor happiness behavior. | Give bad-weather animals calmer movement or shelter preference and readable behavior. Keep the first release gentle; do not adopt happiness loss or destructive storms merely because the reference supports them. |

## Coverage and remaining limits

- **Answered by static evidence:** authority/day forecasts in Stardew; intensity transitions in Minecraft; separate precipitation rendering/assets; indoor/exposure distinction; Minecraft hydration; weather-sensitive fishing; Stardew animal shelter logic.
- **Partially answered:** Stardew crop growth ordering is established, but its full rain-watering call chain was not traced. Packaged Stardew XNB art/data was not decoded, so exact forecast probabilities, texture contents, fish tables and seasonal weather weights are not claimed.
- **Unresolved/out of scope:** runtime appearance/performance, Minecraft animal behavior, lightning damage/spawning chains, snow accumulation and melt, and exact sound mixes. No runtime claim follows from this investigation.
- Agora's cloudy state, seasonal weights, forecast algorithm, transition duration, snow restrictions and gentle bonuses are explicitly original design choices. Daily seasonal weather follows the requested farm-world design; Minecraft provides useful rendering/exposure patterns but its timer cycle is not a daily seasonal forecast.

Earlier farming research remains in [STARDEW-MECHANICS.md](./STARDEW-MECHANICS.md). This note adds weather-specific evidence without replacing its existing limitations.

## Agora implementation

- `packages/shared/src/worlds/weather.ts` owns the versioned seed/day forecast. Day one is clear; snow is winter-only, with season-specific rain/storm probabilities. Tomorrow's forecast becomes the next day's actual weather. No real-world weather service or extra database state is needed.
- The server includes forecasts in `world:time` on arrival and clock updates. Caves omit weather; clients clear old forecasts when entering/leaving worlds. Gameplay changes at dawn; rendering blends over several seconds.
- Outdoor rain and storms water tilled plots for the next dawn, including plots tilled during rain. Offline simulation evaluates each historical day, using the existing one-year catch-up bound. Snow does not water crops. Watering already wet soil costs no energy.
- Rendering uses bounded procedural rain streaks, surface splashes, drifting snow, scene tint and shader-based vegetation sway. Buildings and collision geometry do not sway. Particles stop at terrain/housing heights; caves have no precipitation. Current world geometry has no general roof/interior-volume model, so arbitrary player-built enclosures are not interpreted as roofs.
- Rain/storm/snow shelter animal sprites in their existing coop/barn; feeding and product collection remain available there, and weather causes no production loss or damage. The forecast explains this behavior.
- Procedural rain ambience follows the existing Sounds preference, waits for a user gesture, mutes in hidden tabs, and is disposed on world exit. Reduced motion disables sway/lightning/splashes and uses sparse stationary precipitation.
- **Fishing remains pending:** this checkout has no playable fishing action (P17.34). `fishingWaitMultiplier` is a tested integration hook (rain/storm 0.8, snow 1.1, otherwise 1); it does not currently change any playable action. No fishing minigame is claimed.
- FR/EN HUD buttons show today's weather and tomorrow's forecast and open a keyboard-accessible explanation. No destructive lightning, snow accumulation, freezing, movement penalty or real-world location tracking is included.
